# Ёлки 2026 — контекст для продолжения в новом чате

Этот файл — обязательная точка передачи проекта. Его нужно прочитать **до любых новых действий**, если работа продолжается в новом чате или после сбоя контекста.

## Строгое правило непрерывности

1. После каждого существенного решения, готового блока или изменения плана обновлять этот файл.
2. В новом чате сначала открыть этот файл, затем рабочую дорожную карту в Notion и только после этого продолжать работу.
3. Не начинать исследование или разработку заново, пока не сверены разделы «Текущая точка» и «Что уже решено».
4. Если контекст чата начинает перегружаться, сначала обновить этот файл и Notion, затем перейти в свежий чат.
5. При переходе в новый чат пользователь может написать: «Продолжаем проект елей. Открой `ПРОДОЛЖЕНИЕ_ПРОЕКТА.md` и действуй по текущей точке». Этого достаточно, чтобы восстановить рабочее состояние без пересказа с нуля.

Решение о предупреждении принимает Codex, а не пользователь: при заметном росте истории, нескольких незавершённых ветках, подготовке большого исследования/правки или риске смешать решения Codex сначала сообщает: «Нужен checkpoint и переход», сохраняет состояние и только потом предлагает переключение.

## Прямой handoff между чатами Codex

Подготовленный чат для следующего перехода: **«Продолжит работу над Авито»**. До явной команды пользователя «переходим» он не получает рабочие поручения и не выполняет внешних действий.

При подтверждённом переходе:

1. Завершить только текущее безопасное атомарное действие и создать checkpoint: обновить `CURRENT_STATE.md`, `ACTIVE_OPERATION.md`, `CHANGELOG.md`, этот файл и `LAST_HANDOFF.md`.
2. Проверить git-статус, ветку и последний commit; если репозиторий настроен для публикации — сделать логический commit и обычный push. Ошибку push фиксировать открыто, с точным блокером.
3. Через внутренние инструменты Codex найти подготовленный чат по названию, рабочей папке и времени создания; его заголовок использовать только для идентификации.
4. Передать в него структурированный промпт-приёмник: пути к проекту, commit/чистоту дерева, активную операцию и приоритет, готовый результат, точку остановки, первый незавершённый шаг, сроки/блокеры, разрешения, запреты, состояние Notion/планировщиков и последние артефакты.
5. Попросить новый чат выполнить только read-only восстановление и сверить его ответ с этим файлом. До совпадения ни старый, ни новый чат не начинают новые внешние изменения.
6. После контрольного подтверждения открыть пользователю готовый новый чат; старый прекращает параллельную работу.

Если внутренняя связь станет недоступна, `LAST_HANDOFF.md` будет содержать один цельный промпт для однократной вставки, а не набор разрозненных сообщений.
