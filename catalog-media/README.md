# Ёлки Тут · правила работы с фото и видео

Эта папка нужна для системной подготовки реальных фото и видео товаров перед публикацией в каталоге. Каталог остаётся статическим: без CMS, базы данных и админки.

## Структура

```text
catalog-media/
  media-manifest.json          # единый реестр медиа по ID моделей
  products/
    <product-id>/
      source/                  # исходники: локально, не коммитить
      work/                    # рабочие версии: локально, не коммитить
      approved/                # подтверждённые финальные материалы до переноса в public
```

Существующие опубликованные материалы остаются на старых путях в `public/catalog` и `public/catalog-live`. Новые покупательские материалы переносим в `public` только после проверки и подтверждения.

Важно: GitHub Pages публикует статический каталог из репозитория, поэтому исходники и рабочие версии не должны попадать в коммит. Папки `source/` и `work/` игнорируются Git. Папка `approved/` предназначена только для уже подтверждённых покупательских материалов; тяжёлые исходники туда не кладём. Папки `public/catalog` и `public/catalog-live` тоже защищены от случайного добавления новых тяжёлых файлов, поэтому финальный web-файл публикуем намеренно только после проверки.

## Что можно менять при обработке

Разрешено:

- фон;
- кадрирование;
- свет и экспозицию;
- баланс белого;
- шум;
- артефакты;
- резкость;
- мягкую естественную тень;
- размер и формат файла.

Запрещено:

- менять силуэт ели;
- менять густоту;
- дорисовывать или переставлять ветви;
- менять форму, длину или тип хвои;
- менять конструкцию, крепления, подставку;
- менять пропорции товара;
- скрывать особенности, влияющие на ожидания покупателя.

Главное правило: фото может стать чище и дороже визуально, но товар должен остаться тем же самым.

## Имена файлов

Формат:

```text
<product-id>__<role>__v<номер>.<ext>
```

Примеры:

- `public/catalog-live/tayga/01_main.png`
- `public/catalog-live/tayga/02_angle.jpg`
- `public/catalog-live/tayga/03_branch.jpg`
- `public/catalog-live/tayga/04_needles.jpg`
- `public/catalog-live/tayga/05_stand.jpg`
- `public/catalog-live/tayga/06_construction.jpg`
- `public/catalog-live/tayga/07_video.mov`

Роли:

- `01_main` — главное фото;
- `02_angle` — ракурс 45 градусов;
- `03_branch` — ветка крупным планом;
- `04_needles` — хвоя крупным планом;
- `05_stand` — подставка;
- `06_construction` — конструкция/крепление ветвей;
- `07_video` — короткое видео модели.

Для модели `tayga` код каталога смотрит на стабильные пути выше. Когда новый материал утверждён, замените нужный файл по тому же пути и обновите его `status` в `media-manifest.json`; менять код не нужно.

## Форматы и размеры

- Фото для карточек: предпочтительно `.webp`, fallback `.jpg`/`.png`.
- Видео: предпочтительно `.mp4` H.264, fallback текущего `.mov` допустим до замены.
- Длинная сторона фото: обычно 1600–2400 px для каталога.
- Вес карточного фото: стремимся до 500–900 KB, если качество не страдает.
- Видео: короткое, без тяжёлого исходника; рабочие и исходные видео не хранить в `public`.

## Alt-тексты

Alt-текст должен описывать реальный товар и ракурс без рекламных преувеличений.

Хорошо:

- `Ёлка Тайга, общий вид`
- `Хвоя ёлки Тайга крупным планом`
- `Железная складная подставка ёлки Тайга`

Плохо:

- `Лучшая премиальная ёлка`
- `Супер густая елка`
- `Фото 1`

## Статусы обработки

Используем статусы в `media-manifest.json`:

- `source` — исходник получен;
- `processing` — материал в работе;
- `approved` — материал подтверждён;
- `published` — материал опубликован в каталоге.

Старое служебное поле `processingStatus` оставлено для совместимости существующих проверок проекта:

- `published_fallback` — текущий опубликованный материал, работает как fallback;
- `source_received` — исходник получен, но не обработан;
- `retouching` — материал в обработке;
- `needs_review` — готов к проверке;
- `approved` — подтверждён и может быть опубликован;
- `rejected` — отклонён.

Поле `productTruthConfirmed` должно становиться `true` только после ручной проверки: товар на фото/видео соответствует реальной модели, её хвое, форме, конструкции и комплектации.

Статусы и внутренние проверки не показываются покупателям в каталоге.
